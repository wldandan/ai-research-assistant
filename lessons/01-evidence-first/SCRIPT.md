# 第一节逐段讲稿：怎样判断 Agent 的回答有依据？

所属课程：《用 Python 和 LangGraph 做一个有据可查的资料研究助理》。形式：声音＋编辑器/终端录屏，不出镜。目标成片18分钟，允许15–20分钟；安装、填写凭据和课后暂停练习不计入成片。

这是首节试讲版：将原大纲第1节的证据问题，结合第3/6节的真实轨迹做一次导览，不在这里展开后续实现课。原七节80分钟暂保留为规划，试学后再调整全课时长，不能把本节18分钟与原第1节6分钟同时相加计为已完成课程。

学员只需能读Python字典/列表。本节结束后，应能从记录指出：模型选择的检索词、工具实际返回的来源，以及一句回答是否由原文支持。暂不要求安装SDK、实现图、修改路由或配置供应商。

以下引号内为口播正文；“操作/观察”为留给录制者的动作，不读出。按自然语速读，不为凑时长放慢；每段时间包含指定的操作、阅读和判断停顿。最终时长以试读剪辑为准。

## 00:00–01:20｜先看任务，不先看框架（1分20秒）

操作：编辑器打开课程README标题，然后打开最终真实记录，定位normal.answer；只展示公开字段。

“这门课里，我们要用Python和LangGraph做一个资料研究助理。它收到问题以后，可以自己选择检索词，调用一个查笔记的工具，再根据查到的资料回答。

今天先把这个过程看清楚。先不安装环境，也不逐行读代码。我们只回答一个问题：屏幕上这句话，到底凭什么可信？

比如这条回答，说Agent loop由模型决定动作、执行工具、回传结果，再决定继续还是停止。它后面带着一个N01。看起来有出处，但一个编号就足够了吗？

先记住两个检查动作：找到它实际查到了什么，再把回答和原文逐句对照。今天会看三个问题：资料里有答案、资料里没有答案，以及换一个主题。最后你也要自己判断一条回答。”

观察：留8秒让学员读答案；光标停在[N01]，不要快速滚屏。

## 01:20–03:10｜资料库有多小，证据就有多具体（1分50秒）

操作：打开data/notes.json，先展开N01再展开N02，字号足以完整看到每条text。

“我们先看它能查什么。这个演示的资料库只有两条笔记，不是整个互联网。第一条是Agent循环，编号N01；第二条是会话记忆，编号N02。

每条都有三个字段。id是来源编号，topic是检索时使用的主题，text才是笔记正文。编号用来定位，不能代替正文中的理由。

N01说，模型决定动作，程序执行工具，把观察结果交回模型，然后模型再决定继续还是停止。它还说，最大轮次限制用来防止无界循环。请注意，它并没有说Agent可以自动完成所有任务。

N02说，会话记忆保存此前对话；上下文预算有限，需要保留系统目标和近期有效资料，不同会话应当隔离。

这里的工具做的是简单关键词匹配，不是向量检索，也不能保证理解任何表达。等一下出现空结果，只能说明这次搜索没有在这两条资料中找到匹配，不能说明世界上没有这个问题的答案。”

观察：N01正文留12秒；N02正文留12秒。用光标对照id和text，避免选中整屏。

## 03:10–04:20｜这是历史真实请求，不是现场重演（1分10秒）

操作：打开evidence/minimax-live-2026-10-17-batch.json头部，展示时间、model、requested_budget；再定位runs。

“下面看的是2026年10月17日保存的真实API运行记录。不是固定写好的模型回答，也不是这次录屏正在重新调用。我们先用保存的记录，保证你能看清每一步。

当时使用MiniMax-M3。这里的型号是这份证据的运行条件，不是课程代码必须使用的型号。代码从配置读取模型名。换模型后，检索词、调用次数和措辞都可能变化，要重新验收。

这个演示最多允许四轮模型请求、三次工具调用。一次调用一个工具算一次，同一轮提出两个请求也算两次。预算是上限，不要求每次用满，也不是精确费用保证。”

观察：头部只停公开字段。不要打开.env或CC Switch。保留6秒读预算。

## 04:20–08:00｜正常问题：是谁决定去查资料？（3分40秒）

操作：展开normal记录，依次展示query→nodes→tools[0].arguments→output→answer。每次仅聚焦相关字段，保留上下文标签。

“第一个问题是：请根据课程资料解释Agent loop。

先看nodes，它记录走过哪些节点。节点就是这个流程里负责一项工作的步骤。这里依次是model、tools、model：先请求模型，再执行工具，再请求模型。

关键是中间发生了什么。tools里面的arguments表示模型提出的工具参数。这次模型选择的检索词是Agent loop，limit为三，表示最多返回三条。这不是我在Python代码中给这个问题写死的答案分支。

模型提出要用search_notes，不等于它自己执行了Python。程序检查工具名、参数以及剩余预算，检查通过以后，才运行检索函数。工具只查本地这两条笔记。

再看output。这次返回N01，正文就在这里。我们把程序实际返回、可回查的材料叫作这次回答的证据。不是模型提到了一个编号，它就自动成为证据。

工具结果还要送回模型。call_id用来标识模型提出的这次调用，回传结果会关联同一个调用编号。否则，模型只知道自己提出过请求，并不知道程序实际找到了什么。完整消息如何拼接，我们在实现课再拆。

第二个model节点收到结果后，给出下面这句话。请自己比较：决定动作、执行工具、观察回传、继续或停止，以及最大轮数限制，原文里是不是都有？这里是有的，所以这条回答不仅有编号，内容也受N01支持。

这就是本课要观察的Agent循环：模型选择下一步，程序执行允许的动作，再把结果交回模型。LangGraph负责把这些步骤和继续、结束的规则连接起来。图控制执行边界，模型选择搜索参数和回答内容。”

操作/观察：按顺序定位字段约40秒；对照原文与答案留20秒。最后提问“谁选择关键词，谁执行函数？”留8秒，再口播：“这次关键词由模型选择，函数由程序执行。”

## 08:00–10:30｜没有资料：回答不足也是合格结果（2分30秒）

操作：展开no-evidence：query、工具参数、output=[]、evidence=[]、answer、status及budget。

“第二个问题换成：资料中如何解释不存在的天文星系XYZ？

先别看结论。你已经知道资料库里只有Agent循环和会话记忆，合理预期是什么？应该查不到支持这个主题的材料。

这次模型选择了XYZ galaxy astronomy作为关键词，工具返回空列表。空列表是一次正常检索的结果，不是程序报错，也不是供应商断线。

最终回答是：资料不足，当前课程资料没有匹配内容。这里没有编造来源编号，状态是insufficient，意思是当前资料不足。这次运行通过了课程的验收，因为任务要求根据资料作答，没有证据时就应当承认不足。

请区分两句话：当前资料没有匹配内容；世界上不存在这个星系。前一句是这份记录支持的结论，后一句需要别的证据。我们的助理不能偷偷把问题变成互联网常识问答。

这里用了两轮模型、一次工具，没有用满三次。预算允许再查，不等于每次必须再查。模型也可能换关键词重试；只要实际行为守住预算和证据边界，就应按实际记录判断。”

观察：问合理预期后留10秒；空列表与不足答案对照留15秒。不要把insufficient说成供应商错误。

## 10:30–13:20｜换问题：同一轮可以提出两个工具请求（2分50秒）

操作：展开changed-question，突出两个独立call_id及arguments、各自output，最后回到nodes和answer。

“第三个问题是：请根据课程资料解释会话记忆memory。它是一次新的运行，不是接着上一个天文问题继续聊天。

这次记录有两条工具调用。第一条查会话记忆memory，找到N02；第二条查memory agent loop，返回N01和N02。两个请求都有自己的call_id，结果要分别对应，不能只拿其中一条回传。

再看nodes，仍然是model、tools、model。它不是先问模型、执行一次、再问模型、再执行一次。这里是模型在同一轮提出两次请求，程序在一个tools节点中逐项执行，再把两份结果送回去。支持同轮多工具，不等于程序在并行执行它们。

工具预算按调用数算，所以这里用了两次，剩一次。程序会先检查整批参数；如果一批请求超过剩余额度，就拒绝整批，不偷偷截掉后面的请求或增加预算。

最后的答案只引用N02：保存此前对话、保留目标和近期有效资料，以及隔离不同会话。虽然第二次搜索也返回N01，答案并不需要把所有出现过的编号都贴上去。引用应该对应支持这句话的原文。

这次额外搜索未必必要，但记录是真实的。我们不把它改成理想轨迹。第一节先学会看懂它，后续再讨论如何减少重复检索。”

观察：两条参数/结果逐一定位约30秒，nodes留8秒，N02和答案对照留12秒。

## 13:20–15:20｜自动检查通过，还要人工读一遍（2分钟）

操作：并排展示N01原文与下方“教学反例”，然后打开batch-initial.json的no-evidence.answer/status。

教学反例（手工构造，必须在屏幕上标注）：`[N01] Agent 能自动完成所有任务。`

“现在看一条我手工改写的反例，不是真实模型输出：N01，Agent能自动完成所有任务。

编号是真的，结论受原文支持吗？不支持。原文描述的是一个循环，以及防止无限循环的轮数限制，并没有保证任务都能完成。

程序中的编号检查，只能判断有没有检索、来源是否来自本次返回等窄规则。真编号配错误结论，仍可能逃过这种检查。所以还需要人逐句读原文，判断有没有夸大、偷换或添加外部知识。

再看一次真实失败。首次修复多工具后，无资料场景曾写出并未检索到的N01，还错误描述预算已经耗尽。程序把它判成failed，我们保留了这份记录。后来收紧通用证据提示，没有增加预算，也没有删除错误引用来凑通过，再用相同三个问题重跑，才得到前面的通过记录。

这证明的是这些具体运行。它不证明模型以后每次都可靠，也不证明任何资料、任何问题都能成功。对我们来说，失败原因可见，比一张全绿截图更有用。”

观察：反例留8秒让学员判断；真实失败定位约15秒，不朗读整段长答案。

## 15:20–17:10｜跟着做一次证据判断（1分50秒）

操作：新建未保存的编辑器文本，写三个问题：①谁选择检索词？②依据来自哪里？③这句话是否被原文支持？再回到changed-question。

“现在轮到你。只用刚才的会话记忆记录，不需要配置API，回答三个问题。

第一，这次模型选择了什么检索词？第二，最终答案引用的N02在哪里实际返回过？第三，‘不同会话应隔离’这句话，在原文中能不能找到依据？

你可以现在暂停，写三行答案，再继续。我们在片中留一点时间，让你自己先找。”

观察：固定20秒静默阅读，可保留轻微光标提示但不揭晓答案。

“核对一下：第一次关键词是会话记忆memory，第二次是memory agent loop；N02在两次工具结果中都出现过；隔离不同会话，就是N02正文最后一句。这三个回答分别对应模型的选择、程序的真实返回和语义上的支持。

如果你只写‘因为带N02，所以可信’，还差最后一步：读正文，确认这句话确实是它支持的。做完这一步，你已经能检查这个小助理的一次回答，而不是只看它是否顺利退出。”
