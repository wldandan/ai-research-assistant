# 第一节录屏操作清单

配合[SCRIPT.md](SCRIPT.md)。交付目标：18分钟试讲成片，15–20分钟可接受；声音＋编辑器/终端，不出镜。当前交付为脚本和清单，尚未录音、录屏或完成时长实测。

## 录制前

- [ ] 打开本课独立目录；预先关闭通知、私人文件及无关窗口。
- [ ] 1920×1080、16:9，编辑器字号建议22–26；录10秒样片，回放确认JSON文字清晰、麦克风无破音。隐藏小地图及无关侧栏，长文本开启自动换行。
- [ ] 不打开.env、CC Switch、密钥管理器、终端环境变量；不在画面里执行env、printenv或输出配置。课程无需展示凭据才能讲清本节。
- [ ] 预开README.md、data/notes.json、live_agent.py、research.py，以及下方两份真实记录。只展示记录里的公开字段，不展示SDK原始内部消息或推理内容。
- [ ] 成功记录：evidence/minimax-live-2026-10-17-batch.json。失败记录：evidence/minimax-live-2026-10-17-batch-initial.json。不要改写这些证据。
- [ ] 屏幕固定可见标签“2026-10-17 真实API历史记录回放”；首次展示型号时补“型号可配置，本次记录使用MiniMax-M3”。
- [ ] 按讲稿试读一次并计时。目标18分钟；超过20分钟优先压缩重复解释及滚动等待，不删除三个场景、反例判断和学员自测。少于15分钟先检查是否漏了对照阅读和操作，不硬拖语速。

## 分段拍摄：可分9段录，按时间轴拼接

| 成片位置 | 打开的材料/操作 | 必须录到的观察 | 容易误讲的点 |
|---|---|---|---|
| 00:00–01:20 | README标题→normal.answer | 回答和[N01] | 不是带编号就可信 |
| 01:20–03:10 | notes.json逐条展开 | id/topic/text，两条正文 | 两条教学笔记不是互联网知识库 |
| 03:10–04:20 | batch.json头部→runs | 日期、型号、4/3预算 | 明示历史回放，不称现场调用 |
| 04:20–08:00 | normal的query/nodes/tools/answer | Agent loop；N01；2轮/1工具 | 参数由模型选，Python执行；工具结果需回传 |
| 08:00–10:30 | no-evidence同字段 | 空output/evidence；insufficient；2轮/1工具 | 资料不足不等于程序崩溃或世界无答案 |
| 10:30–13:20 | changed-question两条调用→nodes→answer | 不同call_id；N02/N01；2轮/2工具 | 同轮两请求，程序逐项执行；非并行演示 |
| 13:20–15:20 | N01＋手工反例；initial的失败 | 假结论用真编号；空结果假引用失败 | 手工反例与真实失败必须分别标明 |
| 15:20–17:10 | 三个自测问题→changed-question | 20秒思考；揭晓关键词/来源/原文 | 不提前用光标暴露答案 |
| 17:10–18:00 | research.py函数名→README | 下一节查什么 | 不开始逐行实现讲解 |

操作时每次只高亮一个字段；滚动到位再说，阅读时不继续滚动。长答案用换行展示，不缩小字号。不要把不同运行剪成同一次连续执行。

## 可选：现场请求补录（不要求执行，不计入基础18分钟）

本次无需重新调用供应商。若录制时选择补录，安装和本地.env需提前完成；不要在录屏中填写或查看Key。先在本课目录确认命令，录屏只显示请求命令及公开结果。使用自己的可用配置，保持默认4轮/3次工具预算：

```bash
uv run --frozen --extra live --env-file .env python demo.py --live --provider minimax --query '请根据课程资料解释 Agent loop'
uv run --frozen --extra live --env-file .env python demo.py --live --provider minimax --query '资料中如何解释不存在的天文星系 XYZ？'
uv run --frozen --extra live --env-file .env python demo.py --live --provider minimax --query '请根据课程资料解释会话记忆 memory'
```

- [ ] 现场补录标注“本次现场运行”，另记日期和实际模型名，不覆盖历史JSON。
- [ ] 三个命令分别启动独立运行，不讲成多轮会话记忆测试。课堂问题在研究“会话记忆”，不代表Demo已经实现跨请求持久记忆。
- [ ] 等待超过预留时长，停止口播；可剪去等待但标注“等待已剪辑”，不得伪造耗时。若使用历史回放接讲，明确切换标签。
- [ ] 出现配置错误就停止；不展示Key排错。出现failed/error/budget_exhausted照实留证，不临时提高预算换取成功；主讲可回到已保存且明确标注的历史记录。
- [ ] 工具次数、检索词、答案与历史不同，按新记录重写相关口播；若没出现同轮双工具，可另用原changed-question历史片段讲解，不拼成新运行。

## 剪辑与交付验收

- [ ] 成片15–20分钟；记录实际时长，而不是只引用脚本计划。
- [ ] 全程无需人像，鼠标操作与旁白同步；字幕中的N01/N02、call_id、insufficient准确。
- [ ] 三个场景的问题、工具参数、真实结果、答案、状态和预算均可读；视频没有声称每次都必然通过。
- [ ] N01/N02最终回答与原文对照；真实失败保留失败标签，手工反例有明确标签。
- [ ] 未泄露凭据、个人窗口或私有推理；不把资料不足解释成世界不存在。
- [ ] 观众能完成片中三个自测问题；课后练习只需阅读记录即可完成，不强制购买API或提交个人信息。
- [ ] 保存成片和字幕后找3–5名会基础Python但没看过项目的人试学，记录卡住的时间点、三个自测答案、是否混淆模型选择和程序执行。未试学不标整课已发布。

录制者填写：试读时长____；成片时长____；字号样片通过____；证据/反例标签通过____；隐私回放通过____；试学日期与问题____。
