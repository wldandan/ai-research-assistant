# 有预算的通用多工具兼容：真实验收

2026-10-17。使用与上轮相同的MiniMax-M3和三个原问题，默认预算仍为最多4轮模型、3次工具调用。模型由RESEARCH_MODEL配置；实现没有模型名分支。Chat Completions与Responses共用批次校验/执行逻辑，实际供应商验证本次仅覆盖MiniMax Chat。

## 最终结果与人工核对

| 场景 | 状态/退出码 | 模型轮数 | 工具次数 | 耗时 | 人工核对 |
|---|---|---:|---:|---:|---|
| 正常查询 Agent loop | report / 0 | 2 | 1 | 4.58秒 | 定义、观察回传与最大轮数限制均由N01直接支持 |
| 没有资料：XYZ星系 | insufficient / 0 | 2 | 1 | 4.86秒 | 实际检索为空，明确资料不足，无虚构引用 |
| 换问题：会话记忆 | report / 0 | 2 | 2 | 5.43秒 | 保存对话、上下文取舍和会话隔离均由N02直接支持 |

换问题的节点为model → tools → model；两个独立call_id的搜索在同一模型轮提出，程序逐项执行并完整回填，随后模型回答。N01也被第二次搜索返回，但最终只引用实际支持答案的N02。三条回答无额外外部知识推断。

[完整脱敏运行记录](minimax-live-2026-10-17-batch.json)包含参数、工具公开输出、来源、回答、预算、耗时和运行源码SHA256。revision记录的是运行时基准HEAD，实际未提交改动由source_sha256定位。凭据仅内存读取，不写证据；不保存私有推理。未采集token usage，无法据耗时计算实际费用。

## 失败历史和修订

- [旧串行限制记录](minimax-live-2026-10-17.json)：1通过/2失败，模型发出多工具后被拒绝。
- [首次批次兼容记录](minimax-live-2026-10-17-batch-initial.json)：按程序状态为2通过/1失败；无资料回答虚构N01及预算耗尽，被检查器正确拒绝。人工复核还发现首次正常/换问题含原文未直接支持的扩展说明，因此也不作为忠实摘要成功示例。
- 最后仅收紧通用提示：短答、直接证据、空结果明确不足、不描述预算、不提供示例来源编号；保留检查器和原预算。最终结果见上表，没有删除失败答案中的引用来制造成功。

## 实现与验证边界

同轮多工具按实际调用数计预算，先验证整批工具名、JSON参数、非空且跨轮唯一call_id；非法或超预算整批拒绝。运行时异常保留实际尝试计数和先前完成结果，终止运行，不宣称运行回滚。额度用完只允许模型回答，不增加预算。CLI可显式配置两个上限。
